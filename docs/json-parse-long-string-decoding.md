# JSON 长转义字符串解码优化与验收

基线：`69a49d1160d91f7fb846b8cce80b5d0fb5c81b72`（`perf(json): reuse string prefixes and predict numeric runs`）。
本轮在当前分支实现并验收独立的长字符串解码路径，保留原标量解码方法的源码。

## 实现

- 已解码长度至少 128 字符时进入独立 helper；短字符串直接调用原标量方法。没有转义的字符串继续走原有 CopyChars。
- 每段先处理 32 个字符的标量前缀，长普通片段以 16 字节 NEON 块同时检查反斜线并复制；覆盖一/双字节源与结果的四种组合。
- 允许开头单个转义后接长内容；若后续片段的短前缀又遇到转义，将余下源位置与结果长度交回原标量解码方法。
- 原有扫描器已经验证转义和结果字符宽度。剩余解码长度同时约束安全的源前缀及输出空间；分配、GC 根和禁止 GC 的作用域保持原契约。
- 条件编译限制为小端 NEON；非 NEON 调用路径保持原样。

## 验收协议

- Apple M1 Pro / macOS ARM64 Release，4 个平台工作线程。冻结基线及正常 Ninja 重编译的候选二进制、源码、构建参数和输入哈希。
- 每格四对，顺序 AB、BA、BA、AB；每进程两次预热、九次计时，全结果树指纹校验。
- 同时检查进程中位数之比与配对比值中位数：同步回退上限 3%，异步 5%。
- 计时包含自然 GC、异步排队、前台构建及 Promise 完成；准备、显式轮前 GC 与校验不计入 API wall time。
- 预先规定：若进程边界观察到外部编译器，保留该格完整配对为诊断，等待六秒空档后重测整格；不根据耗时挑选样本。
- 最终 109 格、872 个合格进程、7,848 个计时批次全部通过。另保留 6 组观测到编译干扰的配对记录，共 48 个进程。
- CPU / RSS 为整进程数据，不作为解析阶段 CPU 或分配量。

## 正确性和保留的负面证据

- Release / DCHECK 各 41 项：14 个正常 JS 脚本、7 个 GC 压力脚本、1/2 worker 配置、16 个原生异步测试及两套 API 的 JSONTestSuite；DCHECK 压力项启用堆验证。
- 两套 API 各 293 条 JSONTestSuite 与冻结参考逐行一致。新增 `test/json/parse-string-decode.js` 的 7,444 次校验及摘要与基线一致，包含三参数 reviver 的原始 source。
- Android ARM64 / ARM32 的修改翻译单元编译通过；未进行设备运行或性能验证。核心 GN 头依赖、diff 空白检查通过；cpplint 无新增修改行问题，保留七条原有警告。
- 上轮将标量解码改为通用 helper 的组合原型，在密集转义同步对照中回退约 6%；本轮将回退目标改回原标量方法。旧原型和所有负面样本保存在上一轮探索目录。
- 本轮孤立重链接初筛的 Canada 20 MB 同步约回退 3.04%，另有三条进程边界编译干扰记录。它们未被覆盖；最终采用完整生产构建的预定全矩阵作决定。
