日期：2026-10-27（Asia/Taipei；实验始于 10-26）。父提交
0728b45cbd8e4e415ee1b0d4603b97e2270b924e，其中受测原版引擎代码为 db1b562。

**状态：完成目标修复并采纳当前最小补丁，明确保留一项同步控制例外。** 20 MB 目标、全部 async 项、35/36 个同步项、全部微基准和正确性检查通过。CITM 20 MB 同步 parse 的八轮配对中位数回退 3.009%，原定 3% 门槛仍标记为未通过；这项约 3% 的回退作为工程取舍保留。

本轮把可复现开销定位到前台对象构建中的 GC 标记队列发布与互斥锁路径。
最终修复在 [marking-worklist.h](../src/heap/marking-worklist.h) 中仅为 macOS ARM64
把对象标记队列的最小局部段容量从 64 提高到 256，以摊薄满段发布的同步成本。
已有的部分段发布、工作窃取、标记和 GC 触发机制继续使用原实现。
更大的段会改变满段发布的频率；JSON API 与前台 64K 工作量预算保持原实现。

## 归因与边界

[混合嵌套 JSON.parse 报告](json-mixed-parse-fix-mac-arm64.md) 的同步修复已在父分支。
本轮处理其 [20 MB async 长尾后续事项](json-parse-async-stack.md#2026-10-26-后续事项20-mb-四任务-async-单轮长尾)。
历史 pair=2 缺少阶段记录，不能事后还原它的确切原因。以下结论来自新复现与因果对照：

1. 相同二进制的 A/A 配对也出现约 27.5% 的单轮差值，不能把所有慢样本归因于版本源码变化。
2. 逐任务记录 worker、前台切片、排队、原生资源回收和 GC 回调的 wall/CPU 时间。
   20 MB worker 大体保持 40–42 ms，新慢组的增加主要在前台物化及 GC。
   例如 60 字段最快/最慢四分位的 worker wall 中位数为 40.88/40.92 ms，
   前台 wall 为 90.92/119.71 ms，GC 回调累计为 33.12/42.00 ms。
3. 实际原版二进制的采样栈显示 MarkingBarrier::MarkValueLocal 经
   PublishPushSegment 进入 pthread mutex 等待。采样进程不参与性能验收。
   线程计数器显示前台主要在性能核执行，慢组的周期增幅高于指令增幅。
4. 固定同一诊断二进制中的队列放置位置能重现耗时差异，但简单队列对齐、分离锁与队列
   元数据均没有稳定收益。因此没有保留地址填充，也不把具体缓存行机制写成已证实结论。
5. 改为直接控制对象标记段的容量：在较慢和较快两种固定布局下分别旋转 64/128/256/512
   四档，同一二进制、相同存储和 JSON 算法。256 在两种布局的 10/20 MB 都改善，
   因而进入新的未插桩资格验证。

前台、GC 和 worker 阶段可能重叠，不能相加后当作 Promise.all 延迟；GC 回调也不是
收集器内部所有开销的完整分解。桌面测量采用相邻配对与轮换顺序，不是独占实验机结果。

## 正确性与测试改进

208 项基线/Release/DCHECK 检查命令通过：基线 58 项、候选两套构建各 75 项，
覆盖 JSON、JSON.clone、并发/增量标记、写屏障、弱引用、任务 teardown 和 MessagePack。

改用绝对路径后通过，初始失败日志与修复后日志均保留。

18 个大型输入的完整树指纹、canonical UTF-8 字节数和 SHA-256 与冻结参考一致，

两路共 586 次执行通过；非法 UTF-8 文件沿用原排除口径。

[test-json-async.cc](../test/cctest/test-json-async.cc) 在 worker 完成后、第一次前台
切片前主动启动增量标记，再检查跨片 GC 后的键、内容和浮点字段独立性。

故障栈定位到该断言，同一二进制重跑通过；原版另做 12 次重复通过，失败证据保留。

## 未保留的候选

- 128K JSON 分片上限：未插桩固定矩阵中，12 字段 20 MB 汇总慢 0.52%、配对中位数慢
  2.12%，10 MB 配对中位数慢 5.30%，否决并恢复 64K。
- 缓存键匹配后复用直接构建器：前台指令减少，但两类总耗时四轮汇总慢约 2.05%/1.39%。
- 新对象初始化省略字段屏障（initfix）：通过 208 项检查和 20 MB 目标，但完整控制及
  唯一允许的复核后，60 字段 10 MB 仍慢 6.27%，配对中位数慢 7.14%；312 个正式进程
  全部保留，候选否决。同二进制慢布局下，前台 CPU 虽下降，GC 累计却从约 8.5 增到
  19.5 ms，说明局部指令收益可以被 GC 时机变化抵消。
