Further JSON.parseAsync / JSON.stringifyAsync Android optimizations
2026-10-04. Baseline: 2425ff46cb9916309a8b66bcee8e15767bb34e15.
Branch: codex/json-async-android-round2.
Result: verified repeatable gains for both APIs on ARM32/ARM64, with no >=5%
slowdown remaining in the extended checked controls. Final candidate: fusion-v4.

Implementation and rationale

1. Bounded decimal conversion: DoubleStrtod already limits its exact-integer
   path to <=15 decimal digits. That value fits both uint64_t and binary64's
   exact integer range. ReadExactUint64 removes the generic overflow test on
   every digit in that path. Long DiyFp inputs retain the original reader;
   rounding, powers of ten, exponent handling and parser grammar are unchanged.
   This shared routine also affects synchronous JSON.parse, Number and
   parseFloat, so those are checked against a frozen numeric bit-pattern oracle.

2. Cached object keys: when the async property iterator already holds an
   internalized key and the builder is on its expected final map, compare the
   rooted key directly with the descriptor. Avoid allocating an expected-key
   handle on a successful match. Keep existing field generalization, mutable
   HeapNumber ownership, indexed/duplicate-key handling and slow fallback.
   This is a modest materialization optimization, not object cloning.

3. ARM64 large Smi capture: defer individual integers of magnitude >=10000
   to a native integer part, then format them on the worker. Keep shorter
   integers in the existing punctuation/literal runs. The part remains 16
   bytes and fits the existing three-bit kind. Numeric arrays retain their
   established bulk representation. ARM32 keeps its original capture path:
   extra parts outweighed submission savings in its measurements.

4. Numeric worker memo: cache native shortest-number text in 16 direct-mapped
   entries, keyed by exact binary64 bits. Collisions simply reformat and replace
   an entry. Finite text needs at most 25 characters, including the negative
   fixed-format case; each entry has 32 bytes. Zero emits "0"; nonfinite values
   emit "null". Enable the memo only for jobs with >=64 captured numbers and
   initialize only empty-entry markers. Every 64 nonzero uses, fewer than eight
   hits disables the memo for the remainder of the job. This covers a unique
   suffix after repeated values as well as a unique prefix. No V8 heap objects
   are retained or accessed on the worker.

5. Adaptive worker string scanning: complete short unescaped values directly
   in the parser loop, retaining source, width and cache metadata. Outline the
   longer/escaped decoder so it does not enlarge the numeric loop. After 32
   ordinary code units, a bounded native-word probe and integer NEON vectors
   skip ordinary input. Full words/vectors are read only within the validated
   span; the shared scalar predicate handles the tail. UTF-16 width comes only
   from consumed input, and the first SWAR stop is exact despite borrow effects
   on later lanes. A short escape run switches once to a separately compiled
   scalar loop. Value strings explicitly discard property-index state so the
   compiler removes key-processing logic from that scalar specialization.
   Both loops preserve 4096-code-unit cancellation spans. Non-NEON and big-endian
   targets use the shared scalar scan; performance here is measured on Android.

Timing method

Both ABIs run on the same rooted OnePlus 6 / Snapdragon 845, serial 885841c1,
Android 15 / Lineage 22.2. NDK 27.3.13750724 is installed at
/Users/james/software/android/sdk/ndk/27.3.13750724.
Use one benchmark process at a time, big cores 4-7 (taskset f0), four worker
threads, and policy4 performance governor. The runner restores the previous
governor in finally. Device temperature, frequency, binary hash, raw wall and
submission samples, and whole-process resource observations accompany rows.
Battery temperature is recorded; it is not a per-core temperature measurement.

The matrix has 26 workloads, parse/stringify, one/four jobs, sync/async,
baseline/candidate and two reversed-order passes. Two warmups and nine measured
rounds per process give 18 samples per binary per comparison. Pooled sample
medians are reported; percent less time = 100*(1-candidate/baseline). A four-job
time is for the entire batch. Synchronous calls are sequential; async calls
overlap. Input creation, expected output, result validation and forced GC are
outside the API timing. Entry measures synchronous submission; wall measures
Promise completion. Whole-process CPU/RSS also includes setup, validation and
GC and cannot establish API-only memory savings.

Every comparison showing >=5% slower wall time is repeated with four reversed
passes and 15 measured rounds (60 samples per binary). Small-object single-call
latency is sensitive to worker wakeup/scheduling. A separate test aggregates
1000 batches, with one/four calls per batch, to resolve sustained small-call
overhead. It is a complementary workload; its results do not erase the isolated
single-call measurements.

Build and scope limits

Baseline and candidate use identical Release O2/C++20/API21 configurations,
without LTO or PGO, with NDK libc++_shared, and Intl/Wasm/sandbox/static roots
disabled. build-android.sh is the starting reference; its Wasm setting and
Linux-host assumptions differ from this Mac-host configuration. Revalidate the
embedding's production configuration and target devices before claiming a
general production gain. These results concern one phone and synthetic inputs.

The Mac GN adaptation is in out/json-android-review: Torque runs on the Mac
host (ARM32 layouts through -m32); Android ELF mksnapshot runs on the device.
--no-short-builtin-calls is used only for the snapshot generator's teardown
issue, not benchmark d8. Temporary GN source edits are restored byte-for-byte
and with original mtimes. No production BUILD.gn/build-android.sh change is
retained. A filtered CCTest graph links the JSON tests and necessary helpers,
excluding unrelated debug_helper. Actual links are completed before freezing
executables; freeze.py also checks that binaries do not predate changed source.

Validation

Actual final fusion-v4 binaries passed 84 focused checks: 27 native tests
per ABI plus five JavaScript suites in normal, --stress-compaction, and
--no-json-stringify-fast-path modes per ABI. Coverage includes exact output
and errors, numerical boundaries, arbitrary binary64 formatting/cache misses,
small-job/cache-window boundaries, individual integer capture thresholds,
reviver source, keyed/indexed/duplicate/changed properties, mutable field
independence after GC, concurrent workers, cancellation/termination, tasks
outliving isolates, discarded completion tasks, realms and native resources.

The new native numerical-text test compares worker output with the original
formatter in both byte widths. The new JavaScript suite tests 20000 random
binary64 patterns, repeated/unique phases, representations and GC. Existing
string-boundary tests cover word/vector and 4096-unit boundaries, control
errors, paired/lone surrogates, values and property keys.

A frozen baseline oracle validates 12019 numerical literals bit-for-bit through
JSON.parse, JSON.parseAsync, Number and parseFloat on each ABI (96152 bit-pattern
comparisons). The corpus includes 1-24-digit values, fractions, signs,
exponents from -400 to400, subnormal/overflow boundaries and negative zero.
No all-V8/test262 suite, sanitizer build, or production embedding was run.
Timing diagnostics use no brittle timing assertions.

Rejected experiments and useful findings

- Deferring every Smi reduced capture work but regressed ARM64 nested inputs
  about 21% with one job and 13% with four. Applying the >=10000 threshold to
  ARM32 also regressed representative Smi workloads about 9-10%. Keep only the
  measured ARM64 threshold variant.
- A values-only cached-key tape iterator gave no convincing object throughput
  improvement; wide records regressed about 5-7%. No vector/tape cloning or
  mutable-field sharing is retained.
- Packing consecutive parsed array numbers into vector runs regressed integer
  parsing about 8%. The numeric tape/materialization representation is retained.
- An unconditional numeric-text memo regressed unique doubles about 7%.
  Low-hit windows and the small-job guard limit that overhead.
- An unconditional worker string helper regressed dense escapes about 24%.
  Subsequent outlined variants exposed short-string and saved-index-state
  costs. Unfavorable matrices and patches are preserved; the v3 matrix was
  deliberately interrupted after its dense-escape regression and is not final
  evidence. Scalar specialization and the short-value path address those costs.
- A fresh rebuilt baseline reproduces the frozen ARM64 binary exactly. In a
  string-helper prototype, ParseJsonNumber's body/address stayed identical
  apart from a call relocation, while Strtod moved by 4096 bytes. Whole-process
  simpleperf runs had roughly the same 15.85 billion instructions, but cycles
  rose from about 7.68 to 8.63 billion and branch misses from 13.8 to 71.8 million.
  Sampling implicated the redundant per-digit overflow loop. The capture also
  includes fixtures/validation/GC and simpleperf emitted an affinity warning.
  This is evidence of code-placement-sensitive behavior; it does not prove a
  specific microarchitectural cause. The bounded reader removes the redundant
  branch by a local arithmetic proof rather than relying on a favorable image.
- Two early exact-digits copies were accidentally made before the final link.
  They are explicitly marked invalid-prelink and excluded from candidate
  validation/results and the final evidence package. Actual linked copies and
  their hashes replace them. Unfavorable valid measurements remain preserved.

Further directions

After these measured changes, object allocation, GC, and foreground field
materialization remain substantial costs. A larger redesign should be driven
by representative application traces: tune capture/native-memory allocation,
job batching/backpressure, and field initialization while proving independent
mutable fields, map transitions, revivers and cancellation. Build with the
actual production LTO/PGO/Intl/Wasm settings and test additional ARM cores.
No unmeasured clone shortcut or universal latency guarantee is asserted here.
