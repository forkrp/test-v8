# Android ARM32 与 ARM64 JSON 解析相对 12.6 的真机性能

在同一台 OnePlus 6（ONEPLUS A6003，Snapdragon 845 / SDM845，Android 15 / API 35）上分别运行 ARM32 和 ARM64 的 `d8`。正式测量从 2026-11-06 01:16:59 到 2026-11-06 02:34:19，时间为台北时间。

原始 `12.6` 提供同步 `JSON.parse`。异步用当前分支的 `JSON.parseAsync`，以 Promise 完成为终点，同时比较原版同步和当前同步。

各组对每个场景的配对中位耗时比取等权几何平均。大文件单任务有 18 个场景，20 MB 四任务有 6 个，50 MB 四任务有 2 个。加速倍数大于 1 表示完成时间更短。

## 构建与对照

A 为本地 `12.6` 的 `JSON.parse`，提交 `cd985f42b1e54328dfa52a01149d9350701df5b8`。B 和 C 分别是 `12.6-jsonparse-async` 的 `JSON.parse` 和 `JSON.parseAsync`，共用提交 `df44c54a61c43fc149da8aa6c73fe23ac35e8c94` 的二进制。ARM32 和 ARM64 各自比较同 ABI 产物。

两个 ABI 均使用 Android NDK r27d（27.3.13750724）、Clang 18.0.4、API 21 目标和 Release 配置。当前构建与原版对齐，关闭 Wasm、ICU、ThinLTO 和 PGO。ARM64 两边共用同一份 NDK `libc++_shared.so`。ARM32 原版使用旧构建的 NEON 编译基线和 NDK C++ 运行库，当前分支采用 VFPv3-D16 编译基线、独立 NEON JSON 内核和静态兼容运行库。ARM32 的差值包含这些构建差异。

当前二进制在独立工作区重新构建，目标快照由手机上的 Android `mksnapshot` 生成。原版复用匹配 `12.6` 的已冻结产物，重新核对源码引用、构建无待执行任务及产物哈希。四份 `d8` 和两份共享运行库的设备文件哈希均通过前后校验。

## 复测控制

正式矩阵包含每 ABI 38 个场景、456 个三联区组、1368 个独立进程和 3744 个计时批次，共执行 5256 次计时 API 调用。每个场景走完 A、B、C 的六种顺序，轮次中交替 ABI，场景顺序按固定种子打乱。

每进程预热一次。单任务测三次，20 MB 四任务测两次，50 MB 四任务测一次。每次先显式 GC，读取文本和完整结果树指纹校验在计时外，自然 GC 保留在计时中。计时用设备进程内的 `performance.now()`。预热和计时的每一份输出均通过固定的 `12.6` 参考指纹校验。

全部进程固定在 CPU 4–7（`taskset f0`），V8 工作线程池固定为四个线程。
测试时 `policy4` 使用 `performance`，结束后恢复为 `schedutil`。进程边界采样的频率为 2,803,200 kHz，电池温度为 31.6–40.2 °C，`aoss0-usr` 为 42.8–66.5 °C。

A/A 额外运行 48 个进程。表中为每对相同原版二进制耗时差值的绝对百分比。

| arm64 | records12-20mb/j1 | 0.77% | 2.26% |

同一设备锁覆盖部署和正式测量。排除的重叠区组数量为 0，原始记录保留所有尝试。小幅变化结合 A/A 波动和六组配对范围解读。
