# Mac ARM64 JSON 解析优化验证

验证日期：2026-10-18 至 2026-10-19。基线：`f3a57e97e8f93a6edc22c8c9feb5688eb8b225fc`。

本轮保留同步数值数组无装箱解析、异步小数值数组直接构建，以及同步字符串的短串特化和长串 NEON/SWAR 扫描。公开 API、worker 所有权和 2 ms 前台软预算保持不变。

## 配置与方法

- Apple M1 Pro，原生 ARM64，macOS 27.0.1；Release `-O3`，无 LTO/PGO，关闭 Intl/Wasm/sandbox，沿用 `out/host/args.gn`。
- 用原始源码重新构建基线，d8 与最初冻结版本逐字节一致，排除了基线编译产物漂移；见 baseline-rebuild-check.json。
- 每个输入分别测试 1/4 个任务，固定 4 个 worker；四轮相邻进程配对，交换基线/候选顺序。每进程预热 2 次，每种模式测量 15 次。同步/异步执行顺序交替，每次测量前 GC，计时期间 GC 保留。
- 输入是字符串；输入生成、UTF-8 转换和结果校验不计入 API 延迟。四任务值是整个批次耗时，不能当作单个任务延迟。
- 22 种输入分别由冻结基线和最终二进制生成，UTF-16 code-unit 长度和内容 SHA-256 全部一致；见 fixture-fingerprints.json。
- 绝对耗时取各进程中位数的中位数；耗时降低百分比为 `1 - 新版/基线`。原始数据另保留每轮配对百分比。若追加控制组，汇总包含原样本和所有复测样本。
- 没有锁核或改变系统电源策略；运行时有其他系统负载。各进程负载与原始样本全部保存，不将小幅波动解释为普遍收益。
- 最终汇总：384 个进程，11520 个计时批次样本，88 个 sync/async 比较项；汇总耗时比和各轮配对降低百分比的中位数均没有 >=5% 的回退。
- 首轮最终矩阵中 long_ascii 单任务异步和 records60 四任务异步各有两轮回退超过 5%；随后对这两类输入追加四轮配对。汇总包含原四轮和追加四轮，未丢弃原来的不利样本。

## 实现与未保留的版本

- 同步数值数组参考固定 V8 14.4 来源 `e368b713b918f6a5ad0cf6db46c4a72c2f375b32` 的无装箱路径，保留原数值转换及混合数组回退。原生缓冲区改为局部存储，并在混合元素递归前释放，不扩大异步路径使用的解析器对象。
- 异步仅优化既有无 reviver 小子树中的纯数值数组；读取 worker 已验证的数量和类型标志，直接填充最终存储。没有改变节点格式、工作量计数或线程归属。
- 同步长字符串调用后台原有扫描内核的原生跨度接口；短一字节字符串使用查表，短双字节字符串使用直接字符判断；密集转义切换到独立标量实现。后台仍保持原入口和 4096-code-unit 取消边界。
- 原数值缓冲区成员版本导致宽对象四任务异步回退，改为局部缓冲区后重新测量；原样本和独立控制组保留。
- 字符串的运行时模式分支曾使密集转义变慢；只拆分标量实现又使短 ASCII 变慢；增加短串路径后继续核对宽对象控制。
- 将内联向量扫描组合进数值优化后，转义输入出现明显回退，组合版本被撤回。最终改用单份扫描函数，并按字符宽度特化短串探测，重新运行组合矩阵。短串统一使用直接字符比较的版本也因 ASCII 回退被撤回。
- 组合版本还暴露宽对象四任务异步回退。小数值数组构建随后独立为不内联函数，避免扩大通用小对象构建路径，再运行独立控制和完整矩阵。
- 不从这些实验推断具体 CPU 微架构原因；未保留原型的源码、二进制和负结果都在证据目录。

## 正确性与范围

- 修正 JsonParseAsyncTermination 的测试前提：40,000 层输入超过 65,536 个物理节点，确定跨片。此前失败发生在 TerminateExecution 之前，不能称为已发现并修复生产终止缺陷。
- 最终 8 项 JS 运行（4 个套件，各普通/移动 GC）和 12 项原生检查通过。新增套件的 940 个对照输入覆盖数值、混合/嵌套数组、边界、错误位置、Unicode、原始/转义代理项，并检查 reviver 与 GC 后的独立可变性；输出与冻结基线一致。
- 额外执行既有 numbers/oracle/differential 模式，对照冻结基线逐字节一致；差分记录见 final-differential.json。
- 只验证当前 M1 Pro 和这套构建配置；没有运行 Android、全量 V8/test262、sanitizer 或生产 LTO/PGO 配置。
