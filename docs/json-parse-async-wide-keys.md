# JSON.parseAsync 宽对象构造优化与同步数字后端

日期：2026-10-29，Mac ARM64。**状态：原异步优化目标已通过验收；后续同步优化与最终 12.6 对比也已完成。** 本页保留第一阶段 `flatfloat` 的历史结果；最终 `blockscan` 实现与独立复核结果见 [最终性能报告](json-parse-final-mac-arm64.md)。

合格版本 `flatfloat` 已通过 56 个边界场景、16 个形状/Unicode 控制、54 个大文件场景，以及 18 份大文件完整结果和 586 次一致性校验。正式性能数据共 1,024 个独立进程、9,792 个计时批次，不包括先行筛选和诊断。

## 目标与改动

原基线为 `3d4e3d8e5`，不是原始 `12.6` 分支。目标是让 64/65 字段对象的单任务和四任务 JSON.parseAsync 至少减少 10% 延迟；同步/63 字段控制最多回退 3%，其他异步控制最多回退 5%。汇总中位数比例和配对比例中位数均须通过。

当前异步改动复用 BuildSmallValue 的局部句柄和已验证键缓存：递归子树保持 128 个物理节点上限，另允许不含子容器、最多 128 字段的对象完整构建，最多 257 个物理节点。它必须放进当前切片剩余的 64K 预算，宽扁平对象完成后立即检查 2 ms 软时限。reviver、深层对象和更宽对象继续走原路径。2 ms 是合作式软时限，分配与 GC 仍可能使单次任务超时。

同步新增独立 json-number-parser.cc，使用固定 fast_float 8.3.2 / 42f254836ee416ffcf2f4e6576260003ac33d48c 处理已验证合法数字的转换。小整数扫描、通用 Number/StringToDouble 和后台数字解析保持原实现。

## 被拒绝的实现及测量限制

- cachekeys：仅恢复键缓存的先行测量未让所有目标达到 10%。
- batchkeys：通用字段批处理在 50 MB 四任务 mixed_nested 和 CITM 出现重复退化，提前停止资格验证，所有 156 个已完成大文件进程样本保留。
- widebatch：收窄为宽对象后，16 个微基准和 54 个大文件控制通过，但 12 字段 mixed 同步四任务在合并八对样本后，汇总中位数仍慢 12.315%，配对中位数慢 2.099%，原门槛未通过。
- flatlocal：更小的局部句柄实现已通过全部正确性检查，8 个目标先行测量提升 16.4%–35.5%；但固定八对同步控制的汇总中位数慢 5.460%，配对中位数慢 1.061%，仍被拒绝。
- flatfloat：真实新增同步转换后端后，该固定八对同步控制汇总慢 0.575%、配对慢 0.360%，当前通过。不能据此把原控制的所有波动归因于数字后端。

相同基线二进制的 A/A 也出现过约 11.7% 单对差异；GC 诊断在两版中均发现 4 次 scavenge 与额外 1 次 major GC 的双峰。插桩结果仅用于诊断，没有替代原未插桩失败样本，也没有豁免失败门槛。新候选测量前冻结了按场景连续运行 AB/BA 的顺序，原阈值、默认 GC 参数和自然 GC 均保留。
