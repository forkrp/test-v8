# Tape 回收优化后 Android JSON 解析与 12.6 的真机对比

在同一台 OnePlus 6（ONEPLUS A6003，Snapdragon 845 / SDM845，Android 15 / API 35）上分别运行 ARM32 和 ARM64 的 `d8`。正式测量从 2026-11-06 11:30:28 到 2026-11-06 12:13:42，时间为台北时间。

A 是本地 `12.6`（`cd985f42b1e5`）的 `JSON.parse`。B 和 C 是当前 `16ce4d2fbfdc` 的 `JSON.parse` 和 `JSON.parseAsync`。C 计时至 Promise 完成。

## 构建与对照

基准提交为 `cd985f42b1e54328dfa52a01149d9350701df5b8`，当前 `12.6-jsonparse-async` 提交为 `16ce4d2fbfdca50982d72570cf4056ee7efb93d8`。两种 ABI 各自比较同 ABI 的产物。

两个 ABI 均使用 Android NDK r27d（27.3.13750724）、Clang 18.0.4、API 21 目标和 Release 配置。当前构建与原版对齐，关闭 Wasm、ICU、ThinLTO 和 PGO。ARM64 两边共用同一份 NDK `libc++_shared.so`。ARM32 原版使用旧构建的 NEON 编译基线和 NDK C++ 运行库，当前分支采用 VFPv3-D16 编译基线、独立 NEON JSON 内核和静态兼容运行库。ARM32 的差值包含这些构建差异。

当前二进制来自 tape 回收改动的真机验收构建。构建补丁与提交差异一致，源码哈希和 Ninja 无待执行任务状态均已核对。目标快照由手机上的 Android `mksnapshot` 生成。原版使用本地 `12.6` 对应的冻结产物。设备文件通过了计时前后的清单哈希校验。

## 复测控制

本轮采集 40 个场景、240 个三联区组、720 个独立进程和 2772 次计时 API 调用。ARM64 复用部分为 216 个三联区组和 2484 次计时 API 调用。每个场景覆盖 A、B、C 的六种顺序。

每进程预热一次。单任务测三次，20 MB 四任务测两次，50 MB 四任务测一次。每次先显式 GC，读取文本和完整结果树指纹校验在计时外，自然 GC 保留在计时中。计时用设备进程内的 `performance.now()`。预热和计时的每一份输出均通过固定的 `12.6` 参考指纹校验。

全部进程固定在 CPU 4–7（`taskset f0`），V8 工作线程池固定为四个线程。

测试时 `policy4` 使用 `performance`，结束后恢复为 `schedutil`。进程边界采样的频率为 2,803,200 kHz，电池温度为 26.3–38.5 °C，`aoss0-usr` 为 35.2–62.9 °C。
