# JSON.parse / JSON.parseAsync 扫描优化（2026-11-04）

本轮以 `ed8d2e7330933453b5561914aca1960313d12904` 为冻结基线，在当前分支
`12.6-jsonparse-async` 保留两项扫描优化。该基线已经包含上一轮相对
`97d74878a` 的改动，本报告中的增益是进一步的改善。

## 保留的实现

- 后台数字解析：连续两次数值结果为非 Smi 后，优先调用现有数字转换器，避免先扫描整数前缀再由转换器重复扫描。遇到 Smi 清零预测计数；128 字符窗口、长字面量取消检查和原有错误回退保持原语义。
- 同步 NEON 字符串扫描：短字符串探测失败时，保留已经验证的前缀位置及字符宽度位。首次转义仍按原始字符串起点判断是否密集；将探测函数标记为不内联，避免把回退状态带入递归解析循环。其他平台的非 NEON 入口不增加该属性。

生产代码仅修改 `src/json/json-parser-background.cc` 和 `src/json/json-parser.cc`。
未采用新的分配策略、共享缓存、线程池或写屏障改动。

## 测量方法

- Apple M1 Pro / macOS ARM64 Release，4 个平台工作线程。候选使用正常 Ninja 完整重编译的二进制；孤立对象重链接只用于初筛。
- 每格 4 对比较，顺序 AB、BA、BA、AB；每进程 2 次预热、9 次计时。
- 同时检查进程中位数之比和配对比值的中位数：同步最多回退 3%，异步最多回退 5%。
- 每次结果做完整树指纹校验。计时包含自然 GC、异步排队、前台物化和 Promise 完成；输入准备、显式轮前 GC 和结果校验在计时外。
- 最终 68 格 / 544 个进程 / 4,896 个计时批次，全部通过。每个进程前等待观察到的编译任务结束，进程边界未发现活跃编译器。
- CPU / peak RSS 为整进程数据，包含启动、预热、校验和显式 GC，不能解释为解析阶段 CPU 或分配量。

## 未保留的候选

以下均为每格 2 对的初筛结果，完整负面样本仍在原始目录和证据 JSON 中；不得与最终二进制的正式结果混用。

| 候选 | 结论 |
| --- | --- |
| 仅一个非 Smi 就直接转换 | 交替 Smi / double 异步微基准回退约 7%，收窄为两个连续非 Smi。 |
| 用前一个数组的元素类型提示下一个数组 | Canada 20 MB 同步回退约 13%，数对微基准回退约 17%，淘汰。 |
| 未隔离热函数的字符串前缀复用 | 转义字符串有收益，但 mixed_nested 20 MB 同步回退约 3.3%；最终保留不内联版本。 |
| 仅复用遇到特殊字符的短前缀 | Canada 20 MB 同步回退约 4.3%，淘汰。 |
| 大输入空数组分配到老生代 | CITM 20 MB 同步快约 9%，但 Canada 50 MB 回退约 4%；移出热函数后仍回退约 6%，淘汰。 |

Canada 20 MB 没有空数组，因此不能把该控制回退归因于老生代分配；目前没有证明其微架构原因。
采样用于定位数字转换、字符串扫描和 GC 热点，未将跨线程样本数当作 API 阶段耗时百分比。
